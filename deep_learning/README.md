**BloodMNIST** using k-Nearest Neighbors (1.1), linear classifiers (1.2), and a
neural network (1.3).

All figures in `figures/` were generated by the scripts in `scripts/`, which
reproduce the notebook code outside Colab so the plots can be regenerated.

## Components

Import with `#import "../lib.typ": *`.

| Component | Use |
|---|---|
| `#eq[...]` | Display equation |
| `#note(title: [...])[...]` | Short aside |
| `#choice(title: [...])[...]` | A design decision *and its justification* |
| `#limitation(title: [...])[...]` | A caveat |
| `#codeblock(caption: [...], explain: [...])[...]` | Code excerpt with a required explanation |
| `#fig(caption: [...], reading: [...])[...]` | Figure plus how to read it |
| `#restable(columns: ..., caption: [...], ...cells)` | Results table |
| `#todo[...]` | Grey placeholder, visible so it cannot slip into the hand-in |

`codeblock` requires `explain` and `fig` takes `reading` on purpose: the rubric
rewards code and figures that are *explained*, not merely present.

**Table cells go inside the parentheses, comma-separated.** Trailing `[...]`
blocks on their own line are not passed as arguments and render as literal text:

```typst
#restable(
  columns: (auto, auto),
  caption: [...],
  [*Header*], [*Header*],
  [cell], [cell],
)
```

## Rubric

Six criteria, 5 points each. Where each is addressed:

| Criterion | Where |
|---|---|
| Theoretical description | "What it does" section of each method chapter |
| Experimental design | `data-and-setup.typ`, plus each `#choice` block |
| Presentation and structure | Document structure and headings |
| Visualizations | Every `#fig`, with labels and a stated reading |
| Discussion of results | `discussion.typ`: implications, limitations, improvements |
| Code examples | Every `#codeblock` and its `explain` |

Two easy things to lose points on: design choices must be *justified*, and the
discussion needs implications **and** limitations **and** improvements.

## Reproducing the figures

The scripts in `scripts/` run the same models as the notebooks and write the
plots straight into `figures/`. They read the cached dataset from
`~/.medmnist/bloodmnist.npz`, which `medmnist` downloads on first use.

```bash
python scripts/run_knn.py        # kNN sweep, test eval, confusion matrix
python scripts/run_linear.py     # SVM + softmax grid, weights, loss curves
python scripts/run_nn.py         # network grid, test eval  (~5 min)
python scripts/run_examples.py   # class example grid, per-split counts
python scripts/run_neighbours.py # nearest-neighbour sanity check
```

Needs numpy, matplotlib and scikit-learn. `run_nn.py` is the slow one.

Note these scripts apply the float cast described under Known issues; the 1.1
notebook itself does not, so it will still report ~17.6% until that line is added.

### Results

All four models on the same 1,000 test images. Guessing gives 12.5%.

| Model | Best setting | Validation | Test | Balanced test |
|---|---|---|---|---|
| **Neural network** | 500 hidden, lr 0.1 | 88.0% | **83.9%** | **81.6%** |
| kNN | k=13, L1 | 79.4% | 75.2% | 72.5% |
| Linear, SVM | lr 5e-7, reg 1e3 | 75.0% | 71.4% | 68.6% |
| Linear, softmax | lr 1e-6, reg 1e3 | 70.2% | 66.8% | 64.3% |

### Known issues in the notebook code

- **1.1 needs a float cast.** BloodMNIST loads as `uint8`, and squaring a pixel
  value overflows, so `X_test ** 2` and the dot product both give wrong
  distances. Cast with `.astype(np.float32)` before the reshape. Without the cast
  kNN scores 17.6%; with it, 75.2%. The report documents this as a pitfall.
- **1.3 hinge gradient** sets the correct class's gradient to zero instead of
  minus the number of violated margins, so hinge training will not descend
  properly. Unused here: all results use softmax.
- **1.3 Adam branch** updates weights but never biases. Unused here: all results
  use plain SGD.

### Caveats worth knowing

- Every model trained on 5,000 of 11,959 images, tuned on 500 of 1,712, tested on
  1,000 of 3,421, for runtime reasons.
- For the linear classifiers and the network, the winning setting sits at the
  edge of the search grid, so those numbers are lower bounds.
- The network reaches 99.7% training accuracy against 88.0% validation, so it is
  overfitting heavily.
